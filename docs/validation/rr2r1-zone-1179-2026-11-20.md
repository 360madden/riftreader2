## Existing components reused

The installed `RiftReader2` addon already has the desired `RR2R1` reference stream. `addon/RiftReader2/reference.lua` emits fifteen statused player fields, including the printable-ASCII string `zone` read from `Inspect.Unit.Detail`, every 0.5 seconds after a reader nonce is bound. The reference stream is wrapped as `RR2R1|<JSON>|ENDRR2R1` and keeps eight frames. Both the installed `reference.lua` and `main.lua` on AMD-DESKTOP match the repository files byte-for-byte by SHA-256. **Matching installed files do not prove that the currently loaded addon is active or bound.** `/rr2bind <32 lowercase hexadecimal nonce>` is the existing manual binding interface; the wrapper does not send it.

`MemoryDiscoveryCommand.ScoutCopyTypedAsync` is an already implemented read-only `.NET 10` scanner. Its target contract requires an exact PID, process-start tick count, executable SHA-256 and current-session revalidation; it is not tied to the old game's field RVAs. This work did not modify the native scanner.

## Delivered

1. `scripts/probe_physical_rr2r1.py` now permits **only** the two verified executable hashes (1177 and 1179), projecting the actual verified process SHA into every scanner request, copied-source check and resume receipt. Wrong SHA/process/epoch still refuses, and historical 1177 replay remains valid.
2. `scripts/inspect_typed_resource.py --resource zone --session-id NONCE --snapshot PATH` now extracts the existing RR2R1 statused string-zone field, preserving the complete strict reference/nonce/epoch/player/chunk-hash checks. Historical `--historical-rrapival2` cannot select this new resource.
3. `scripts/correlate_native_zone_rr2r1.py` combines a source-hashed native zone report and a source-hashed RR2R1 snapshot **offline**. It refuses mismatched process ID, start epoch, build, module when supplied, player unit ID, absent or malformed/case-inconsistent `z[16 uppercase hex digits]` zone strings, and snapshots more than the caller's bounded time window apart (default 15 seconds, maximum 30). It preserves the original independent source hashes, reader session/epoch/sequence and exact 100 ns time comparison. Output is `matching-candidates` or `mismatched-candidates`, **never** world-instance or navigation authority. The nonce is a reader-session challenge, not cryptographic source authentication.
