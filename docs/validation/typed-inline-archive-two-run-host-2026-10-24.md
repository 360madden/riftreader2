## Reused components and new boundaries

- New scripts/verify_typed_inline_archive.py validates a **single guest-produced ZIP** with precisely two run folders, run-01/ and run-02/. Each must include its unchanged input.request.json and generated index.json, plus only the capture-01..08.request.json and capture-01..08.snapshot.json pairs named by its manifest.
- Before extraction it checks the **caller's expected full ZIP SHA**, exact PID/start-ticks/game binary SHA in requests/manifests/snapshots, pinned published bundle SHA, original-request and per-file SHA provenance, each saved 4 KiB chunk's Base64/length/SHA, and acquisition separation of at least one second. Partial scans or zero captured candidates remain negative, scoped evidence.
- Strict caps: **16 MiB ZIP**, **8 MiB decompressed**, **512 KiB per file**, **40 members**. Rejects duplicate/traversing/absolute/extra paths, ZIP symlinks, encrypted members, missing files, digest inconsistencies, unknown schemas and duplicate JSON properties. The verifier reads from exactly the hashed ZIP bytes and only then creates a new no-overwrite output directory with an archive-proof.json receipt.
- Receipt scope is **offline-content-integrity-only**, with typedFrameQualified=false and nativeXyzQualified=false. The unchanged C# strict snapshot loader and typed-wire inspector remain the frame-qualified evidence gate.
- New repeatable scripts/host_trial_typed_inline_archive.ps1 uses PowerShell 5.1, its own allocated native buffer, the previously published single-file V2 executable, Windows Compress-Archive, and the same Python verifier. It neither opens a network listener nor accesses VMware.
