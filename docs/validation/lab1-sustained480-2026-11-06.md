## Failed attempt and bounded read handling

The unchanged first attempt failed `live-receipt-unavailable` after 85.2304 s
and 93 accepted samples. Its failed summary remains under observer-c below.
The receiver atomically replaces `latest.json`; the shared reader separately
checks pathname size and opens it, so a publication race can produce this
error even for complete JSON. The error can also represent refused file types,
sizes or I/O failures; the error alone does not prove which cause occurred.

Commit `1802c4b` changes only the observer's post-initial poll loop: unavailable
reads are never accepted, are counted in `transientUnavailableReads`, and may
recover only within the unchanged strict 4.5-second accepted-sample gap. All
other errors propagate; initial acquisition is unchanged. Persistent failures
still fail qualification. Content, identity, capture-gap, advancement, expiry,
player/epoch and drift gates are unchanged. The new run used a new pin and
output directory; no failed output was promoted. Independent review and the
observer/feedback/pin suite passed (53 tests).
