# RiftReader2 whole-codebase bug hunt — October 28, 2026

Scope: **RIFT-Lab-2 only**; Casting addon, Lua contracts, native-memory acquisition,
C# reader/live state, VMware guest tooling, and build/test infrastructure.
Six independent read-only reviewer tasks covered different subsystems.
RIFT-Lab-1 was untouched; no game input, restart, or health-loss experiment
was performed. Findings below distinguish reproduced/confirmed defects
from lower-confidence risks.

## Confirmed bugs fixed and regression-protected

| Area | Problem | Defensive correction |
| --- | --- | --- |

## Casting follow-up: unified dashboard and facing/LOS truth boundary

The next user review found visual inconsistency between glossy protected native
`RiftButton` controls and flat diagnostic controls. Casting **v0.3.0**
implements one 584 x 602 dashboard rhythm and matching flat macro-bearing
restricted `Frame` actions. Decorative child layers use limited mouse
masking, while the protected frames have no ordinary click handlers. Regression
tests assert frame type, visual tokens, caption sizing, mouse masking,
manual-only macros and picker clearance. Source and guest files are SHA-256
matched in a separately checked **Lab-2-only** deployment under
`artifacts/rr2-lab2-hud-deploy-20261028-06/`
(run `17c9896ae6e642608adadda309b4f665`). The game was not clicked,
reloaded or restarted; the visual and protected-click live gate is pending.

Facing and generic hostile-target line of sight are **not implemented or
qualified**. The last saved native RIFT `Inspect.Documentation` report from
before the October 27 patch lists coordinates but no facing/yaw, and limits
`Inspect.Unit.Detail.blocked` to group members. Neither a successful historic
cast nor approximate XYZ proves continuous facing or hostile LOS. Version
0.3.0 shows separate amber **UNVERIFIED** chips and limits green status to
**API READY**. Recover and interpret current-build in-game API docs before
attempting detection. No native yaw offset is promoted from the old build.

The increment passed **61 focused Lua 5.1/Casting tests** and the complete
**894-test Python suite (2 expected skips)**. The prior 519 .NET and
native/broader checks above were run before this UI-only Lua change and are
not misrepresented as rerun.

## Known follow-ups — not marked fixed

1. **P2:** Failed typed native-scout publication can leave its uniquely named
   staging directory; add exact-path cleanup and a deterministic failure test.
2. **Review needed:** Guest maintenance has a 120-second maximum lease,
   while the guest response wait plus transfer and postflight may approach
   that limit. Verify an actual budget overrun before changing coordination rules.
3. **Policy decision:** Zero-realized-displacement wall contact is currently
   rejected instead of given a special semantic classification; do not
   silently promote a candidate meaning without trial evidence.
4. **Unconfirmed API edge:** Whether nonthrowing `EventMacroSet`/`SetVisible`
   can explicitly return `false` requires live-client return-contract proof.
5. Full game restart, controlled health-loss testing, and patch-recovery
   remain outside this milestone's authorization.
