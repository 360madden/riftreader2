# Exact-epoch ZIP claim and received-byte provenance — October 24, 2026

**Outcome: implemented and host-validated end-to-end over localhost; no listener bound to the VM interface and no RIFT guest or coordinator access.** This closes the previous transfer-integrity gap between a guest's declared ZIP checksum and the actual ZIP saved by the existing one-use receiver.

## Reused one-use services

- New scripts/receive_guest_inline_zip_claim.py reuses the existing scripts/receive_guest_snapshot_hashes.receive_once timed, single-delivery HTTP loop. It accepts only the fixed RIFT-Lab-1 guest **192.168.56.128** at VMnet8 host **192.168.56.1:8765**, route **/rr2-typed-inline-zip-claim-oct24-01**, POST with text/plain and a bounded **255-byte** claim. Other peers, paths, methods, content types, replays and malformed bodies are rejected. A live listener requires independent signed-in Windows pythonw.exe, a 30–600-second deadline, exact expected process epoch and an unused receipt path inside ignored artifacts.
- Strict one-line declaration format: **RR2INLINEZIP1|UPPERCASE_ZIP_SHA256|DECIMAL_ZIP_BYTES|PID|EXACT_START_TICKS|UPPERCASE_GAME_SHA256|UPPERCASE_V2_BUNDLE_SHA256**. ZIP size must be 1–16,777,216 bytes. Receipt kind **guest-typed-inline-zip-claim/1** records the declared values and explicitly labels them **guest-declared-only**. The hash claim never transfers ZIP bytes or reads game memory.
- After receiving the claim, the existing scripts/receive_guest_memory_report.py still handles the actual ZIP upload separately: its one-use exact-IP, exact-hash, 16 MiB no-overwrite POST rules are unchanged. Its historical receipt purpose still says content-addressed-guest-map-transfer even when bytes contain ZIP; the new archive verifier explicitly understands that original purpose.
- The existing scripts/verify_typed_inline_archive.py now accepts optional **--claim-receipt PATH --upload-receipt PATH** as a required pair. It validates both saved receipts, the exact fixed guest peer, game process PID/start/game SHA, bundle SHA, the declared ZIP SHA **and byte length**, upload receipt SHA/bytes/destination, and independently verified exact original ZIP bytes. Any mismatch prevents publication. Its new archive-proof.json guestTransfer stanza binds both original receipt SHA hashes to the recovered JSON originals. Omitting both receipts remains valid for an explicitly **host-only** test fixture, with no guestTransfer attribution.
